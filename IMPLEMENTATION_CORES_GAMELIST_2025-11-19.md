## 📁 FICHIERS CRÉÉS

### 1. `CoreMetadataManager.kt`
**Emplacement:** `app/src/main/java/com/retroplay/CoreMetadataManager.kt`

**Fonctionnalités:**
- Détection automatique depuis `https://buildbot.libretro.com/nightly/android/latest/cores.json`
- Cache local (24h) pour éviter requêtes répétées
- Support NIGHTLY et STABLE builds
- Parsing complet des métadonnées (version, license, firmware, etc.)
- Conversion en `CoreInfo` pour compatibilité

**Utilisation:**
```kotlin
// Détecter tous les cores disponibles
val metadata = CoreMetadataManager.fetchCoresMetadata(context, BuildType.NIGHTLY)

// Obtenir les cores pour un ABI spécifique
val cores = CoreMetadataManager.getCoresForABI(context, "arm64-v8a")
```

### 2. `GamelistManager.kt`
**Emplacement:** `app/src/main/java/com/retroplay/GamelistManager.kt`

**Fonctionnalités:**
- Génération automatique de `gamelist.json` avec métadonnées complètes
- Calcul CRC32 automatique pour chaque ROM
- Support récursif (scanne sous-répertoires)
- Format standardisé avec version et metadata
- Fusion de plusieurs gamelists (multi-répertoires)

**Format généré:**
```json
{
  "version": "1.0",
  "console": "nes",
  "games": [
    {
      "id": "1",
      "name": "Super Mario Bros",
      "path": "./Super Mario Bros.nes",
      "crc32": "a1b2c3d4",
      "size": 40960,
      "desc": "...",
      "genre": "...",
      "releasedate": "...",
      "players": "1-2"
    }
  ],
  "metadata": {
    "generatedAt": 1234567890,
    "sourceDirectories": ["/path/to/roms"],
    "autoGenerated": true,
    "totalGames": 1,
    "console": "nes"
  }
}
```

## 🔧 FICHIERS MODIFIÉS

### 1. `CoreDownloader.kt`
**Changements:**
- Méthode `getAvailableCores()` marquée `@Deprecated`
- Nouvelle méthode `getAvailableCoresFromMetadata()` pour détection automatique
- Fallback automatique sur liste hardcodée si erreur

**Avant:**
```kotlin
fun getAvailableCores(): List<CoreInfo> {
    return listOf(
        CoreInfo("fceumm", "...", "..."),
        // ... 30+ cores hardcodés
    )
}
```

**Après:**
```kotlin
suspend fun getAvailableCoresFromMetadata(
    context: Context,
    buildType: BuildType = BuildType.NIGHTLY
): List<CoreInfo> {
    val metadata = CoreMetadataManager.fetchCoresMetadata(context, buildType)
    return metadata.values.map { CoreMetadataManager.toCoreInfo(it) }
}
```

### 2. `WebServer.java`
**Changements:**
- `serveAutoGeneratedGamelist()` utilise maintenant `GamelistManager`
- Génération avec métadonnées complètes (CRC32, taille)
- Format standardisé avec version et metadata

**Avant:**
```java
// Génération basique sans métadonnées
org.json.JSONObject game = new org.json.JSONObject();
game.put("id", String.valueOf(gameId++));
game.put("name", baseName);
game.put("path", "./" + fileName);
// Pas de CRC32, taille, etc.
```

**Après:**
```java
// Utiliser GamelistManager amélioré (Kotlin)
String jsonContent = GamelistManager.generateGamelistJsonString(consoleDir, consoleName);
// Inclut CRC32, taille, metadata, etc.
```

## 📝 NOTES TECHNIQUES

### Cache Cores Metadata
- **Durée:** 24 heures
- **Emplacement:** `context.cacheDir/cores_metadata.json`
- **Timestamp:** `context.cacheDir/cores_metadata.timestamp`
- **Invalidation:** `CoreMetadataManager.invalidateCache()`

### Format Gamelist
- **Version:** 1.0
- **Extensions supportées:** Définies par console dans `getDefaultExtensions()`
- **CRC32:** Calculé automatiquement si possible
- **Metadata:** Optionnel mais recommandé

### Performance
- **Cache cores:** Évite requêtes réseau répétées
- **CRC32:** Calcul asynchrone recommandé pour gros fichiers
- **Scan récursif:** Optimisé pour éviter scans inutiles
